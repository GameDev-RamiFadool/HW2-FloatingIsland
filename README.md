יצרתי משחק דו־ממדי באמצעות Unity שבו השחקן יכול לנוע על אי מרחף באמצעות מקשי המקלדת.

לצורך התנועה השתמשתי ב־`InputAction` מתוך מערכת הקלט החדשה של Unity. התנועה מחושבת בעזרת `Time.deltaTime`, כך שמהירות השחקן אינה תלויה במספר הפריימים בשנייה.

בנוסף, יצרתי ארבע אנימציות הליכה וארבע אנימציות עמידה, לפי כיווני התנועה.

### 🗺️ המיני־מפה

הוספתי מצלמה נפרדת בשם `MiniMapCamera`, שמציגה את האי ואת מיקום השחקן.

המצלמה מציגה את התמונה באמצעות `RenderTexture`, שמוצג בתוך רכיב `RawImage` ב־Canvas, בפינה הימנית העליונה.

מסביב למיני־מפה הוספתי מסגרת בסגנון Pixel Art, עם הכיתוב `HOMEWORK 2`.

כדי שהמיני־מפה לא תוסתר על ידי המגרעת של הטלפון, השתמשתי גם בסקריפט `SafeAreaHandler`.

---

### סעיף א' – מדוע העצמים נראים גדולים יותר לאחר סיבוב המסך?

כאשר מסובבים את המכשיר ממצב אופקי למצב אנכי, יחס הרוחב והגובה של המסך משתנה.

במצלמת Orthographic, השדה `orthographicSize` קובע את מחצית גובה האזור שהמצלמה מציגה בעולם המשחק.

אם נשאיר את הערך הזה קבוע, גובה העולם שמוצג יישאר זהה, אבל במצב Portrait המצלמה תציג אזור צר יותר מבחינת רוחב.

לכן האובייקטים תופסים חלק גדול יותר מרוחב המסך, ונראים גדולים יותר ביחס אליו. במקרה של המשחק שלי, חלקים מהאי אף נחתכו בצדי המסך לפני התאמת המצלמה.

---

### סעיף ב' – פתרון באמצעות סקריפט

כדי לפתור את הבעיה יצרתי סקריפט בשם `CameraAspectController.cs`, המחובר למצלמה הראשית (`Main Camera`).

הסקריפט בודק את מידות המסך, מחשב את יחס הרוחב והגובה הנוכחי, ומשנה בהתאם את הערך `Camera.orthographicSize`.

החישוב מתבסס על יחס המסך המקורי ועל גודל המצלמה שהוגדר עבורו:

**New Size = Reference Size × (Reference Aspect / Current Aspect)**

בדרך הזאת נשמר אותו רוחב יחסי של עולם המשחק על המסך, כך שהאי אינו נחתך כאשר מסובבים את המכשיר.
